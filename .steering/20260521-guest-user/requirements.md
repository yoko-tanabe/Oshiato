# ゲストユーザー機能 要件定義

## 概要

現在 OSHIATO は全ページがログイン必須で、未ログインのアクセスは `/auth/login` に強制リダイレクトされる。
本機能では「ログインせずにアプリへ入れ、ログインユーザーと同じ全機能を使える**ゲストユーザー**」を追加する。

実現方式は **Supabase の匿名認証（Anonymous Sign-in）**。ログイン画面を経ずに“名無しの一時アカウント”を自動発行し、本物の `auth.uid()` を割り当てることで、`user_id` を必須とする既存機能（投稿・チェックイン・推し登録・マイページ）を無改修で動かす。

> **重要な制約**: この機能は**後でコードごと撤去する前提**。フィーチャーフラグは持たず、**撤去容易性を最優先**に設計する。

---

## 機能要件

| # | 要件 |
|---|------|
| G-1 | 未ログインでアクセスしても `/auth/login` に飛ばされず、裏側で匿名サインインしてアプリに入れる |
| G-2 | ゲスト（匿名ユーザー）はログインユーザーと同じ全機能を使える（投稿・チェックイン・推し登録・マイページ・軌跡 等） |
| G-3 | 既存のログイン・会員登録・ログアウト機能は残す |
| G-4 | ゲストは `/auth/login` `/auth/register` にアクセスでき、後から会員登録／ログインできる |
| G-5 | ゲストは `/setup-profile`（プロフィール設定）に強制リダイレクトされない |
| G-6 | マイページでゲスト時のみ「会員登録する／ログイン」導線を表示する（ログアウトボタンは非表示） |

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| 撤去容易性 | ゲスト専用ロジックは新規ファイル1つ（`lib/supabase/guest-mode.ts`）に集約。既存ファイルの変更箇所は全て `// GUEST-MODE` マーカーを付け、`grep` で特定・撤去できる |
| ドキュメント | 暫定機能のため永続ドキュメント（`docs/`）は変更しない。本ステアリングのみに記録 |
| 認証 | Supabase 匿名認証（`signInAnonymously`）。ダッシュボードで Anonymous sign-ins の有効化が前提（手動作業） |
| RLS | 既存 RLS（`auth.uid()` ベース）を利用。匿名ユーザーも `auth.uid()` を持つため原則そのまま通る。INSERT が弾かれる場合のみ調整マイグレーションを追加 |
| データ永続性 | ゲストのデータはブラウザのセッションに紐づく。Cookie 削除・別端末ではアクセス不能（消えてはいない）。マイページの会員登録 CTA で明示 |

---

## スコープ外（今回実装しない）

- 匿名 → 正規アカウントへの**昇格**（`updateUser` でのメール紐付け）。設計上ブロックはしないが実装は将来。
- 匿名ユーザーの定期クリーンアップ（乱立対策）。暫定機能のため許容。
