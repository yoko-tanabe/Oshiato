# decision.md — Phase C: マイページ・投稿管理

## 設計判断の記録

---

### DEC-01: マイページのURL設計

**判断**: 新しく `/mypage` を作成し、TabBar のリンク先を `/oshi` → `/mypage` に変更する

**背景**:
現在の TabBar は「マイページ」タブが `/oshi`（推し管理ページ）を指している。
ラベルと実態がずれているため、本来の「マイページ（統計ダッシュボード）」を `/mypage` に作り、推し管理は `/mypage` 内からのリンクで辿れるようにする。

**代替案**:
- `/oshi` をそのままマイページ化する → 既存の推し管理機能との混在が複雑になる
- `/mypage` と `/oshi` を両方タブに追加 → タブが6つになり UI が窮屈

---

### DEC-02: 統計データの取得方法

**判断**: Supabase JS の通常クエリでデータを取得し、クライアント側で集計する（RPC 関数は作らない）

**背景**:
マイページの統計（投稿数・訪問数・推し別集計）はログインユーザー1人分のデータのみ対象。
データ量が少ないため、複雑な SQL RPC 関数を作るよりもシンプルなクエリ + JS 集計の方が保守しやすい。

---

### DEC-03: `useCurrentUser` の拡張

**判断**: `userId` に加えて `displayName` も返すよう拡張する

**背景**:
マイページとプロフィール編集の両方で表示名が必要。
毎回 `users` テーブルを別クエリで取得するのは冗長なので、共通フックに組み込む。

**影響範囲**: `useCurrentUser.ts` の返り値が変わるが、既存の呼び出し元は `displayName` を受け取らないだけで壊れない（型は追加するだけ）。

---

### DEC-04: SpotEditForm の表示方式

**判断**: スポット詳細ページ内でインライン展開（モーダルは使わない）

**背景**:
モーダルは CSS が複雑になりやすく、モバイルでのスクロール挙動に課題が出やすい。
今回は写真タイル下に編集フォームをインライン展開する方式でシンプルに実装する。

---

### DEC-05: 削除の確認ダイアログ

**判断**: `window.confirm()` を使う（カスタムモーダルは作らない）

**背景**:
削除は稀な操作のため、専用コンポーネントを作るコストより `window.confirm()` のシンプルさを優先する。
Phase G 以降で共通ダイアログコンポーネントが必要になった時点でリファクタリングを検討する。

---

### DEC-06: `bio`（自己紹介）カラムの扱い

**判断**: Supabase ダッシュボードで `users` テーブルに `bio` カラムが存在するか確認してから実装を判断する

**背景**:
開発計画の DB スキーマ定義に `bio` が含まれているが、Phase B の DB マイグレーション時に追加されたか不明。
カラムがなければ今回は `display_name` のみ編集対象とし、`bio` の追加は別タスクとする。

---

### DEC-08: post削除時に spot を削除しない（意図的）

**判断**: `deletePost()` 実行後、紐づく `spots` レコードは削除しない

**背景**:
- 投稿削除後に `spot` への `post` が0件になっても、`spots` テーブルのレコードは残る
- 将来的には「spotに投稿がなくなったらspotも削除」が理想だが、今は実装しない
- 理由: Phase I で「重複投稿マージ」（複数ユーザーの投稿を同一spotにグルーピング）を実装予定。
  その設計が固まる前に spot の自動削除を入れると、マージロジックと競合するリスクがある
- spot の自動削除は Phase I のグルーピング設計完了後に改めて検討する

---

### DEC-07: Storage 画像削除の実装

**判断**: Storage のファイルパスは `image_url` 文字列から substring で抽出する

**背景**:
Supabase Storage の公開 URL 形式は固定:
`https://<project-ref>.supabase.co/storage/v1/object/public/<bucket>/<path>`
`post-images/` 以降の文字列を path として取り出し、`storage.from('post-images').remove([path])` で削除する。
