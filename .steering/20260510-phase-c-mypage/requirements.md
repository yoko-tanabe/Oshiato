# requirements.md — Phase C: マイページ・投稿管理

## 前提条件

- Phase B（Supabase Auth認証基盤）実装済み・ビルド通過確認済み
- `auth.uid()` でログインユーザーを取得できる状態
- RLS（行レベルセキュリティ）が全テーブルに適用済み

---

## 何を作るか

### C-1: マイページ（`/mypage`）

ログインユーザー自身のダッシュボード画面。

| 項目 | 内容 |
|------|------|
| URL | `/mypage` |
| 表示内容 | 投稿数・訪問数・推し別スポット集計のサマリー |
| 追加要素 | プロフィール編集へのリンク、ログアウトボタン移設 |

### C-2: プロフィール編集（`/mypage/profile`）

匿名ネーム・自己紹介を編集するフォーム。

| 項目 | 内容 |
|------|------|
| URL | `/mypage/profile` |
| 編集項目 | `display_name`（匿名ネーム）、`bio`（自己紹介・任意）、`avatar_url`（将来対応） |
| 保存先 | `users` テーブル |

### C-3: 投稿の編集機能

スポット詳細ページ（`/spot/[id]`）から自分の投稿を編集する。

| 項目 | 内容 |
|------|------|
| 編集可能フィールド | `category`、`comment`（`posts` テーブルに `title` カラムなし） |
| アクセス制御 | 自分の投稿のみ編集ボタンを表示（RLS で DB 側も制御） |

### C-4: 投稿の削除機能

スポット詳細ページから自分の投稿を削除する。

| 項目 | 内容 |
|------|------|
| 削除対象 | `spots` レコード + `post_images` レコード + Supabase Storage の画像ファイル |
| UX | 削除前に確認ダイアログを表示 |
| アクセス制御 | 自分の投稿のみ削除ボタンを表示 |

---

## 完了基準

- [ ] `/mypage` でログインユーザーの投稿数・訪問数・推し別集計が見られる
- [ ] `/mypage/profile` でプロフィール（匿名ネーム・自己紹介）を編集・保存できる
- [ ] `/spot/[id]` で自分の投稿に「編集」ボタンが表示され、タイトル・説明・カテゴリを変更できる
- [ ] 自分の投稿を削除でき、画像も Storage から削除される
- [ ] 他ユーザーの投稿には編集・削除ボタンが表示されない
- [ ] `npx next build` がエラーなく通ること
- [ ] `npx next lint` で警告がないこと
- [ ] モバイルサイズ（375px幅）で表示が崩れないこと
