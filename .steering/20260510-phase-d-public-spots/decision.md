# Phase D：設計判断の記録

## is_public のデフォルト値

**決定**: `DEFAULT true`（公開がデフォルト）

**理由**: 既存投稿をすべて公開扱いにする。ユーザーが意識せずに使っても地図が賑わう。
非公開にしたいユーザーは明示的にOFFにする運用。

## is_public を posts テーブルに置く

`spots` テーブルは位置情報のみ管理し、公開/非公開の意味は持たない。
投稿（posts）単位で公開制御するのが自然なため `posts` に追加。

## D-2（ユーザープロフィール）の表示範囲

- 匿名ネーム: 公開（推し活の交流に必要）
- 推し一覧: 公開（レコメンド機能の前提でもある）
- 公開スポット: 公開
- 非公開スポット: 本人のみ

## D-3 の実装方針

MapView の既存クエリは変更せず、RLS に委ねる方針に決定。
別クエリでのマージ案もあったが、RLS が `is_public = true OR auth.uid() = user_id` を自動適用するため、コード側の変更は「投稿ゼロスポットを常に非表示」にする1行のみで十分。

## user_oshis の閲覧範囲

当初「全員公開」で設計していたが、プライバシー保護のため「本人のみ」に変更。
Phase E のレコメンド機能は SECURITY DEFINER 付き PostgreSQL 関数で統計集計するため、
個人の推しデータを外部に返さずに集計は可能。
→ 「誰が何を推しているか」は非公開、「N人が推している傾向」は公開、という設計。

## RLS の競合ポリシー問題

Phase B 実装時に作られた `posts_select_all`（全件 SELECT 許可）ポリシーが残っていたため、
`公開投稿は全員閲覧可能` ポリシーを追加しても非公開投稿が見えてしまっていた。
RLS は複数 SELECT ポリシーを OR で評価するため、1つでも全許可ポリシーがあると意味がない。
→ 古いポリシーを DROP してから新ポリシーを追加する順序が重要。
