# 決定事項: カテゴリ見直し・期間導入・マップフィルター・ナビ改善・レインボーピン

## DC-1: カテゴリ体系

**決定:** 5カテゴリ → 4カテゴリに整理

| 旧 | 新 | 理由 |
|---|---|---|
| 目撃（ooh） | 広告・OOH（ooh） | 「目撃」は曖昧。OOH（Out of Home）広告に限定して意味を明確化 |
| コラボカフェ（collab_cafe） | ポップアップ（popup） | コラボカフェだけでなく期間限定ショップ等も含むため上位概念に変更 |
| イベント（event） | イベント（event） | 変更なし |
| ショップ（shop） | → その他に統合 | 常設ショップは「その他」に含める方が自然 |
| その他（other） | その他（other） | 常設ショップ、聖地なども含む汎用カテゴリ |

**代替案:** カテゴリを増やす（6〜8種）→ 却下。選択肢が多すぎるとユーザーが迷う。

## DC-2: 期間のデフォルト計算ルール

**決定:** 全カテゴリで手動入力可能。未入力時のみ自動計算。

- OOH: デフォルトは投稿日の週の月曜〜日曜を自動設定。開始日は編集不可、終了日は延長のみ可。
- popup/event/other: 開始日・終了日ともに自由入力。未入力時は投稿日〜週の日曜。

**理由:** OOH広告は1週間以上掲出されることもあるため、終了日の延長を可能にした。ただし開始日は投稿日の週に固定し、過去に遡る操作を防ぐ。

## DC-3: マップフィルターの方式

**決定:** マップ上部にチップ型フィルターバー（横スクロール）

- 選択肢: 「すべて」「今日」「明日」「今週」「カスタム」
- フィルターはクライアントサイドで実行（取得済みデータを絞り込み）

**代替案:** サーバーサイドフィルタリング（RPC拡張）→ Phase 1のデータ量では不要。データ増加時に移行検討。

## DC-4: 訪問ログのアクセス方法

**決定:** `/trajectory` ページ内にタブ切り替えUIを追加

**代替案:**
- TabBarに「訪問ログ」タブを追加 → 却下。タブが6個になりUIが窮屈。
- 軌跡マップ内にリスト表示を統合 → 却下。UIが複雑になりすぎる。

**理由:** 軌跡マップと訪問ログは「自分の活動を振り返る」という同じ目的。タブ切り替えで自然にアクセスできる。

## DC-5: レインボーピンの実装方式

**決定:** CSS `conic-gradient` を使ったレインボーボーダー

**代替案:**
- SVGマーカーにグラデーション → 却下。Mapbox GLのカスタムマーカーはDOM要素ベースなのでCSSの方がシンプル。
- アニメーション付きレインボー → 却下。パフォーマンス懸念。静的グラデーションで十分。

**理由:** CSSのみで実装可能。JS変更が最小限で済む。

## DC-6: PC版HEICプレビューの対応方式

**決定:** `processImage.ts` に `createPreviewUrl()` を追加し、ImagePickerから呼び出す

**仕組み:**
1. まず `URL.createObjectURL` + `new Image()` でブラウザが表示可能か判定
2. 表示可能（JPEG/PNG/WebP等、またはSafari上のHEIC）→ そのままblob URLを使用
3. 表示不可（Chrome上のHEIC等）→ 既存の `heic-decode` でデコードし、400pxプレビュー画像を生成
4. デコード失敗 → フォールバックUI（アイコン+「プレビュー不可」）

**代替案:**
- 全画像を常にcanvas変換 → 却下。JPEG/PNG等では不要な処理でパフォーマンス悪化。
- プレビューなしでフォールバックのみ → 却下。HEICは主要フォーマットのため、プレビューできないとUX低下。

**理由:** 既存の `heic-decode` + `resizeAndConvert()` を再利用でき、新規依存なし。変換は表示不可時のみ実行されるためパフォーマンス影響も最小。

## DC-7: 推しカラー選択の方式

**決定:** プリセット8色 + HSLベースのカラーピッカー（色相バー + 明度バー）

**代替案:**
- プリセットカラーを256色に拡張するグリッド → 却下。画面を占有しすぎる。スクロールが大量に必要。
- ブラウザネイティブの `<input type="color">` → 却下。ブラウザごとにUIが異なり、ダークテーマとの統一感がない。
- 色相・彩度・明度の3軸ピッカー → 却下。彩度を固定（70%）にすることでUIをシンプルに保つ。推しカラーとして使いやすい鮮やかさに統一。

**理由:** PowerPoint風の2バー方式は直感的で、事実上無限の色を選択可能。彩度を70%に固定することで、どの色を選んでもピンやバッジで視認性が確保される。
