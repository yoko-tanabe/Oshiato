| 項目 | 内容 |

**背景:**
当初 `src/` も追加対象に含まれていたが、作業中に不要と判断された。
現時点では共有ソースコードの置き場として使う具体的なユースケースがない。

### 決定②：`.claude/` 配下は `.gitkeep` で管理

| 項目 | 内容 |
|------|------|
| 決定内容 | 空ディレクトリを `.gitkeep` で Git 管理する |
| 決定者 | Claude |
| 決定日 | 2026-03-22 |

**背景:**
Git は空ディレクトリを追跡できないため、`.gitkeep` を置いてディレクトリ構造を保持する。
実際のコマンド・スキル・エージェントファイルを追加した際は `.gitkeep` を削除してよい。

---

### 決定③：ルート `package.json` は npm workspaces を採用

| 項目 | 内容 |
|------|------|
| 決定内容 | npm workspaces でモノレポを管理する |
| 決定者 | Claude |
| 決定日 | 2026-03-22 |

**背景:**
将来的に `apps/web` 以外のパッケージ（共有ライブラリ等）が増えた際に対応しやすい。
追加ツール不要で npm 標準機能のみで実現できるためシンプル。

**検討した選択肢:**

| 選択肢 | メリット | デメリット |
|--------|----------|------------|
| npm workspaces（採用） | 標準機能、追加ツール不要 | 大規模モノレポには機能不足 |
| Turborepo | 高機能、キャッシュ機構あり | 学習コストが高い |
| pnpm workspaces | 高速、ディスク効率が良い | pnpm への移行が必要 |
