# requirements.md — Phase A 残件修正

## 作業概要

Phase A（バグ修正・UX改善）の未完了タスクを完了させ、Phase B（認証基盤）への着手条件を整える。

## 対象タスク

### A-4: 位置情報デフォルト改善

- **現状**: 初回訪問時（localStorageが空）に地図が東京（緯度35.6895, 経度139.6917）固定で表示される
- **要件**: 初回訪問時にブラウザの現在地取得を試み、取得できた場合はその位置を初期表示とする
- **フォールバック**: 現在地取得を拒否・失敗した場合は東京をデフォルトとして使用する（変更なし）
- **対象ファイル**: `apps/web/components/map/MapView/MapView.tsx`

### A-5: エラーハンドリング改善（RPC失敗のToast通知）

- **現状**: `get_spots_with_coords` RPC が失敗した際にサイレント失敗する（ユーザーに通知なし）
- **要件**: RPC失敗時に Toast でエラーを通知する（「スポットの読み込みに失敗しました」）
- **対象ファイル**: `apps/web/components/map/MapView/MapView.tsx`

## 完了基準

- [ ] 初回訪問時に現在地取得のプロンプトが表示され、許可した場合は現在地が初期表示になる
- [ ] 現在地取得を拒否・タイムアウトした場合は東京がデフォルトになる（既存挙動を維持）
- [ ] `get_spots_with_coords` RPC 失敗時に Toast エラーが表示される
- [ ] TypeScript 型エラーなし・ESLint 警告なし
