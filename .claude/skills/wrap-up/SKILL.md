# 開発セッション締め作業

作業終了時のドキュメント更新チェックとコミットメッセージ生成を行います。

## 手順

### 1. Steeringドキュメントの確認・更新

現在の作業ブランチを確認する:
```bash
git branch --show-current
git log --oneline -5
git diff HEAD --name-only
```

`.steering/` 配下の最新ディレクトリを特定し、以下の4ファイルを確認する:
- `requirements.md` — 要件の変更・追加はあったか
- `design.md` — 設計の変更・追加はあったか
- `decision.md` — 今回の作業で下した設計判断があるか
- `tasklist.md` — タスクの完了状態は最新か

実装した内容と照らし合わせ、各ファイルに追記すべき内容があれば追記する。
**1ファイルずつ確認・更新し、ユーザーに確認を取ってから次へ進む。**

### 2. 永続ドキュメントの確認・更新

`docs/` 配下のドキュメントを確認する。以下の観点でチェック:
- 新しいコンポーネント・API・DB変更が `docs/` に反映されているか
- 技術スタックや設計方針の変更はあったか

更新が必要なファイルがあれば追記する。
**1ファイルずつ確認・更新し、ユーザーに確認を取ってから次へ進む。**

### 3. コミットメッセージの提案

変更内容を確認してコミットメッセージを提案する:
```bash
git status
git diff --staged
git diff HEAD
```

以下の規約に従ってメッセージを提案する（実行はしない）:
- `feat:` 新機能追加
- `fix:` バグ修正
- `docs:` ドキュメント更新
- `style:` コードスタイル修正
- `refactor:` リファクタリング

**Claudeはコミットを実行しない。提案のみ行う。**
